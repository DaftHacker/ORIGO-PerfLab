# ORIGO PerfLab

ORIGO PerfLab is a small, deliberately stressful game project for measuring ORIGO Engine. It is intended to live separately from the engine repository and to exercise the same runtime APIs used by normal games.

The repository was created as an empty project. This first milestone establishes an actual ORIGO project, a procedural benchmark game mode, an in-game scenario panel, and a reproducible capture script. It is a starting harness, not yet a substitute for verifying runs on the target machine.

## First milestone

The default map creates a camera and directional light. When play begins, PerfLab creates 1,000 default-cube GameObjects from C++ and submits them through the engine's normal scene/render path. The gameplay module can create and clear repeatable workloads without shipping a huge pre-generated map.

The first scenarios are:

- **Static grid:** 1,000, 5,000, 10,000, or 25,000 ordinary renderable objects. Repeated mesh/material state lets ORIGO use its existing batching path while the CPU still has to process the scene.
- **Moving grid:** objects whose transforms change over time, to stress transform updates and dynamic render submission.
- **Physics stack:** 100 or 500 rigidbody/collider cubes over a static floor. This is a real physics workload, unlike a render-only balls demo.
- **Particles:** a sustained transient-particle workload, plus a one-shot particle burst button.
- **Camera sweep:** move the runtime camera around the test field to vary which regions intersect the frustum.
- **Clear:** remove PerfLab-created objects while keeping the authored camera and light.

The UI is intentionally small. For repeatable measurements it can be disabled and the scenario/count selected with environment variables.

## Requirements

- A built PC version of ORIGO Engine (the editor/runtime uses GLFW and desktop OpenGL).
- The ORIGO Engine source checkout that matches the executable you want to profile.
- Windows PowerShell for the supplied .bat and .ps1 helpers. The project itself is a regular ORIGO project and is not Windows-specific.

The game uses ORIGO's built-in default cube and default material. It does not require external mesh, texture, or audio assets.

## Open and play in ORIGO

1. Clone ORIGO-PerfLab.
2. Build the matching ORIGO Engine checkout.
3. Open ORIGO-PerfLab.origoproject with ORIGO_ENGINE.exe.
4. Build / hot-reload game code from the editor's Game menu if the editor has not compiled the project module yet.
5. Press Play. PerfLab should start with 1,000 static cubes and the in-game control panel.

You can also launch the editor directly in play-only mode. This removes the full editor's Scene viewport/panels from the measured runtime and is usually preferable for throughput captures:

~~~powershell
& "D:\Path\To\Origo-Engine\out\build\x64-relwithdebinfo\ORIGO_ENGINE.exe" "$PWD\ORIGO-PerfLab.origoproject" --play-only --auto-play
~~~

The engine checks and loads the project's game module. If the game mode does not start, open the project normally, use Game → Build / Hot Reload Game Code, check Build Output/Console for compile errors, and then run it again.

## Capture a run

The capture helper sets ORIGO's existing ORIGO_FRAME_PROFILE environment variables and PerfLab scenario variables, launches the engine in play-only mode, waits for warm-up and capture to finish, then exits automatically.

~~~powershell
.\Tools\Capture-PerfLab.ps1 -EngineExe "D:\Path\To\Origo-Engine\out\build\x64-relwithdebinfo\ORIGO_ENGINE.exe" -Scenario static -Count 5000 -WarmupSeconds 10 -CaptureSeconds 30
~~~

Outputs go into Results/ and are ignored by Git. The profile text and viewport captures are generated by ORIGO's existing profiler workflow. If the capture does not exit, close the game normally and inspect the engine log; automated exit depends on the profiling capture reaching its requested sample duration.

Supported scripted scenarios are static, moving, physics, particles, and empty. Static/moving object counts are limited to 50,000; physics counts are limited to 1,000. Particle count is a target for an approximate sustained population, not a promise of an exact GPU particle count.

To include the camera sweep, pass -CameraSweep. By default the camera remains fixed for a more comparable baseline.

## What these tests measure

PerfLab is intentionally using ordinary ORIGO game objects for the initial object tests. They measure the complete cost of creating/updating a scene and passing it through the engine; they're not the same as a hand-written OpenGL loop that submits a million vertices from a single GPU buffer.

Use different scenarios to separate the limits:

- Static grid primarily stresses scene size, render-object construction, visibility filtering, instancing/batching, and GPU rendering of visible cubes.
- Moving grid adds per-frame game-side transform changes.
- Physics stack adds collider/body setup, simulation, contacts and transform synchronization.
- Particles exercise ORIGO's transient particle path and its CPU-side particle upload/rendering.
- Camera sweep changes visibility and exposes how the current renderer responds as the view moves.

PerfLab does not yet implement spatial chunk culling. It is meant to give us a baseline that we can use when we later prototype the hierarchical culling design documented in ORIGO-Engine's Docs/RENDER_CULLING_AND_SPATIAL_PARTITIONING_ROADMAP.md.

## Important benchmarking rules

1. Compare the same engine commit, build configuration, machine, resolution, graphics settings, and scenario.
2. Warm up resources before collecting a run.
3. Use median, p95 and p99 frame time as well as average throughput. Averages can hide stutters.
4. Profile CPU scopes and GPU timers separately. ORIGO's per-viewport CPU timings are not pure GPU timings.
5. Keep an unprofiled run as a final throughput check because detailed instrumentation itself can add overhead.
6. Do not compare editor-with-two-viewports numbers directly with play-only/standalone numbers.
7. Record whether VSync is enabled. A monitor refresh cap is not a measurement of uncapped render throughput.

The 160 FPS goal corresponds to a 6.25 ms full-frame budget. It is a target to measure, not a guarantee made by this project.

## Repository layout

- ORIGO-PerfLab.origoproject — project descriptor.
- Assets/Maps/PerfLab.map — minimal authored camera/light scene.
- Assets/Scripts/PerfLabGameMode.h — procedural scenarios and in-game controls.
- GameModule/GameModule.cpp — game-mode registry glue; normally generated by ORIGO.
- CMakeLists.txt — project gameplay-module build definition.
- Tools/Capture-PerfLab.ps1 — automated profile capture.
- Docs/PERFLAB_BENCHMARKS.md — workload definitions and result interpretation.

## Current validation status

The files in this initial commit were authored against the ORIGO Engine gameplay/module API and the current project/map serialization format. The repository is new, and no ORIGO editor executable or Windows build environment is available in this GitHub file-editing session, so this commit does **not** claim a compiled or live runtime validation. The first local gate is: open the project, hot-reload the game mode, play, test all six UI actions, then run one static/1,000-object and one physics/100-body capture and inspect their profile outputs.
